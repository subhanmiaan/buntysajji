# Website audit — October 11, 2026

## Scope and evidence

Reviewed the public storefront, menu, story, gallery, checkout, order tracking code, admin access boundaries, API validation, pricing, promotions, and order-abuse controls. Checked the deployed site in Chrome at mobile width and used existing browser tests for English/Urdu, theme and layout behavior, slow requests, JavaScript failure, and old asset URLs.

- Build and lint passed.
- Nine backend/database tests passed, covering isolated database transactions, RLS, authoritative prices, vouchers, safe retries, phone/network limits, and invalid requests.
- Fifteen loading/language browser tests passed. An additional audit regression covers page titles, CSP errors, gallery preview/original behavior, sitemap, and private-page indexing headers.
- `npm audit --omit=dev` reported zero known production dependency vulnerabilities. This is not a comprehensive security guarantee.
- Live anonymous admin API requests returned 401; admin orders redirected to login. Requests for `.env` and server source returned 404.
- No real customer order was submitted. Existing authenticated admin end-to-end tests modify the shared live catalog/settings; these were not rerun. Admin CRUD, staff acceptance, and live delivery completion therefore remain unverified in this audit. Database tests run against isolated local PostgreSQL-compatible test instances.
- The deployed catalog contained 116 dishes, with four fish dishes lacking priced available variants. Delivery and takeaway were enabled. Turnstile was disabled according to the public checkout configuration.

## Bugs fixed

1. Two inline footer styles violated the Content Security Policy on every public page. Moved them into the stylesheet without weakening CSP.
2. Client initialization replaced every page title with the same repeated restaurant name. Titles now retain the page identity.
3. Gallery thumbnails downloaded original JPEG sheets. Added 600px WebP previews: all six total 359,264 bytes instead of 2,041,175 bytes (82% smaller). Full-size originals remain available when opened. This measures image bytes, not whole-page load time.
4. Missing `robots.txt` and `sitemap.xml`. Added both and excluded checkout, tracking, and admin from indexing using response headers. These directives are not access controls; existing authentication still protects admin data.

## Prioritized improvements

1. **Order verification:** enable the implemented Turnstile integration using the site's Cloudflare keys. Free WhatsApp confirmation is manual: staff must match the sender's number before preparing an order. Clicking the link does not prove phone ownership. Automated OTP is not implemented.
2. **Business accuracy:** supply the four fish prices, confirm delivery coverage/fees, and decide whether to enforce kitchen opening hours automatically. Hours are currently display text; staff must pause ordering manually.
3. **Complete localization:** built-in Urdu labels and many dish names are translated, but custom descriptions, several dynamic messages, addresses, and original menu artwork are not fully bilingual. Add explicit Urdu fields for admin-managed content and a complete message catalog. Have a fluent Urdu reader review the wording.
4. **Admin/operations:** add an isolated staging database for safe authenticated end-to-end tests, shared login/quote rate limits across server instances, admin MFA/recovery, error/uptime alerts, and a tested backup-restore procedure. These were not provisioned during this audit.
5. **Checkout resilience:** review the optional CAPTCHA renewal flow for a checkout left open beyond its human-verification cookie lifetime; currently a refresh may be needed. Validate any payment-provider integration in a separate sandbox before offering online payments. Checkout currently accepts cash only.
6. **Content and accessibility:** confirm current menu-sheet prices against live prices, complete keyboard/screen-reader and contrast audits, and add restaurant-approved delivery, cancellation, and privacy information. No policies or business rules were invented in this audit.

## Limitations

This audit did not include load testing, penetration testing, authenticated production admin writes, actual WhatsApp messages, real payments, or a production database restore. Public pages rendered without horizontal overflow at the audited mobile viewport. Browser checks cannot establish that every device, connection, or assistive technology behaves identically.
